# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`krab` is Kapitan rewritten in Rust: a cargo workspace (Rust 1.85, edition 2024)
holding the inventory engine, an inventory daemon, an incremental compiler, a
language server and the `krab` binary. It reads the same `.kapitan`,
`inventory/classes`, `inventory/targets`, `refs/` and `resolvers.py` as the
Python implementation.

Output must be byte-identical to kapitan 0.36.3 with the omegaconf inventory
backend. Merging, interpolation, resolvers, YAML and JSON emission and compiled
output are ports of Python behaviour rather than fresh implementations of the
same idea. The deliberate differences are listed in `docs/DECISIONS.md`, and a
new one needs a row there before it merges.

## Commands

```sh
cargo build --release                      # target/release/krab
cargo fmt --all
cargo clippy --all-targets --locked        # CI runs with RUSTFLAGS=-D warnings
cargo test --locked
cargo test -p krab-inventory --test fixture          # one test binary
cargo test -p krab-inventory fixture::name_of_case   # one case
```

Tests that need more than cargo:

* `crates/krab-inventory/tests/python_resolvers.rs` and the kadet evaluator test
  (`crates/krab-compile/tests/kadet_runner.rs`) need a `python3` with `pyyaml`,
  `omegaconf`, `kadet` and `jinja2` importable. The kadet test skips without
  them; `.github/workflows/ci.yml` has the versions CI uses.
* The corpus test (`crates/krab-inventory/tests/corpus.rs`) runs only when
  `KRAB_CORPUS` and `KRAB_COMPILED` point at a real inventory and reference
  output.
* `tests/fixtures/expected/*.yaml` is generated by the Python kapitan, not by
  krab: `cd tests/fixtures && PEX_INTERPRETER=1 kapitan generate_expected.py`.
  Every engine behaviour change gets a fixture case plus regenerated expected
  output.
* LSP without an editor: `python3 scripts/lsp-smoke.py <repo> <file> 1:10` and
  `scripts/lsp-smoke-live.py <repo>` (both need `krab` on `PATH`).
* VS Code extension: `cd editors/vscode && npm ci && npm run package`.

After touching loading, merging, interpolation, resolvers, emitters or
compile, run the parity check against a real inventory. CONTRIBUTING.md has the
commands.

Rebuilding does not require stopping anything: each build hashes into its own
daemon socket, so a dev build and the installed release coexist.

## Architecture

`krab-inventory` is the library entry point and stays free of daemon, compile
and CLI concerns. Everything the CLI prints is computed there or in
`krab-compile`; the CLI only formats. `krab-server` wraps an `Inventory` in a
daemon, `krab-compile` and `krab-lsp` sit on top, and `krab` is the binary.

Four invariants cut across all of them.

* Provenance is never optional. `Value` is a JSON-like tree whose every `Node`
  carries an `Origin { file, line, col }` interned in `Sources`, and `merge.rs`
  records every override, list append and merge-time dereference as a
  `MergeEvent`. `explain`, hover and definition all read that data, so a change
  that drops origins breaks three surfaces at once and breaks them quietly.
* Equality and stringification follow Python (`1 == 1.0 == True`,
  `str(None) == "None"`, float `repr`), because those values end up inside
  interpolated strings that have to match the reference.
* Every error is a `Diagnostic` with code, message, origins and `help`, so it
  renders the same through miette, `--json` and the editor.
* The daemon and the local path run the same library code. A feature that works
  only with the daemon, or only without it, is a bug. `--no-daemon`, `--raw` and
  a failed server start all fall back to a local render with identical results.

Engine pipeline (`krab-inventory`): `yaml.rs` parses via the vendored
`saphyr-parser` applying PyYAML `safe_load` YAML 1.1 scalar rules → `classfile.rs`
shapes a file → `inventory.rs` resolves class names (including the reference's
two reclass-compat fallbacks) and memoises a `ClassClosure` per class file →
`merge.rs` applies OmegaConf `unsafe_merge(EXTEND_UNIQUE)` → `interp/` parses and
evaluates `${...}` (the parser follows OmegaConf's ANTLR grammar token for token)
against the resolver `Registry` → `model.rs` reproduces pydantic normalisation of
`parameters.kapitan` (`--raw` skips it) → `emit/` writes PyYAML-, rapidyaml- and
Python-`json.dumps`-compatible output. `python.rs` is the shared Python bridge
(interpreter choice, embedded worker script, newline-delimited JSON), used by both
Python resolvers and the compile crate's kadet/kapitan runners.

`krab-server`: one daemon per inventory directory *and* build. `state.rs` keeps an
index from every path a target was rendered from (plus every path probed while
resolving its class names) to the affected targets, so a new
`classes/common/init.yml` invalidates exactly the right targets. `watch.rs`
debounces `notify` events 150 ms. `protocol.rs` is JSON-RPC 2.0, one document per
line, over a socket named by hashes of inventory path and build. The socket binds
*before* the initial render so a second starter loses cheaply and clients wait on
readiness instead of a timeout. Secrets are never revealed server-side.

`krab-compile`: *exact invalidation or nothing*. A target recompiles only when its
rendered document digest, any path the previous compile read (file opens,
directory listings, imported modules and search-path probes, all recorded by
the Python worker), the documents of targets it read via `inventory_global()`,
the compiler identity, or the compiled output tree digest changed. All of it lives in
`compiled/.krab-manifest.json` next to the output so it travels with it;
`--explain`/`--dry-run` print the reason per target. Within a stale target, kadet
items whose own recorded inputs are unchanged are reused rather than re-evaluated.
`inputs/` holds native input types, `refs/` the reference backends, `pyenv.rs` the
venv krab builds from `.kapitan`'s `compile.python-requirements`, and
`runner/kapitan/` a small bundled `kapitan` package that serves components'
`kapitan.*` imports so the Python kapitan is not needed. `--backend python` runs
kapitan's own input types instead and does need it.

`krab-lsp` is a thin translator: it renders nothing itself. `yaml_index.rs` maps a
cursor to a key path / scalar / `classes:` entry from buffer content, values always
come from the daemon's render of saved files.

`vendor/saphyr-parser` is the upstream crate plus two PyYAML-compatibility
patches (`vendor/README.md`); keep the diff minimal.

## Conventions

* Commit messages: `area: what changed` (`lsp: accept the --stdio flag`).
* `docs/CLI.md` is the flag reference and must stay in sync with `--help`;
  `docs/DESIGN.md` carries the semantics.
* Open work is tracked on the GitHub project board linked from `docs/ROADMAP.md`,
  not in the repo.
* Releasing: bump `version` in the workspace `Cargo.toml` (and
  `editors/vscode/package.json` when it changed), merge, then tag `main`
  (`v2.0.0-alpha.4`); `release.yml` refuses a tag that disagrees with the
  workspace version.

## Environment variables

`KRAB_INVENTORY_PATH`, `KRAB_NO_DAEMON`, `KRAB_PYTHON` (interpreter for
resolvers and kadet), `KRAB_PYTHON_REQUIREMENTS`, `KRAB_CORPUS` / `KRAB_COMPILED`
(corpus test only).
